# Frontend UI Engineering

## Overview

Build production-quality user interfaces that are accessible, performant, and visually polished. The goal is UI that looks like it was built by a design-aware engineer at a top company — not like it was generated by an AI. This means real design system adherence, proper accessibility, thoughtful interaction patterns, and no generic "AI aesthetic."

## When to Use

- Building new UI components or panels
- Modifying existing user-facing interfaces
- Implementing responsive layouts
- Adding interactivity or state management
- Fixing visual or UX issues

## Component Architecture

### Principles

**Prefer composition over configuration** — build focused, reusable pieces.

**Keep components focused** — each component does one thing.

**Separate data from presentation** — keep logic and rendering separate.

## State Management

**Choose the simplest approach that works:**

```
Module-level state      → Feature-wide shared state (extension pattern)
DOM-level state         → Per-element UI state
Chrome Storage          → Persisted user preferences
Event-driven updates    → Cross-component communication
```

**Avoid prop drilling.** In a Chrome extension context, use the YPP settings object and event dispatch patterns already established in the codebase.

## Design System Adherence

### Avoid the AI Aesthetic

| AI Default | Why It Is a Problem | Production Quality |
|---|---|---|
| Purple/indigo everything | Models default to visually "safe" palettes | Use the project's actual color palette |
| Excessive gradients | Visual noise, clashes with design systems | Flat or subtle gradients matching the design system |
| Rounded everything | Ignores corner radii hierarchy | Consistent border-radius from the design system |
| Oversized padding | Destroys visual hierarchy | Consistent spacing scale |
| Shadow-heavy design | Dated appearance | Subtle, purposeful shadows |

## Accessibility

Every interactive element needs:
- Keyboard navigability (Tab, Enter, Space, Escape)
- ARIA labels for icon-only buttons
- Focus-visible styles
- Sufficient color contrast (4.5:1 minimum)
- Screen reader announcements for dynamic content

## Performance

- Throttle scroll/resize handlers with `requestAnimationFrame`
- Use `will-change: transform` sparingly and only when needed
- Clean up all event listeners in disable/destroy methods
- Use CSS transitions instead of JS animations where possible
- Avoid layout thrash — batch DOM reads before writes

## Chrome Extension Specifics

- Always use `addListener()` from BaseFeature for tracked cleanup
- Panels must close on Escape key and outside click
- Use `setProperty` with `!important` only for filter/style override survival
- CSS custom properties (`--ypp-*`) are preferred over inline styles
- Respect YouTube's DOM lifecycle — re-initialize on SPA navigation
